## What this is

Class website for "Siber" — lesson notes, announcements, and a shared cash ledger
(_kas_). Forked from an internal `dashboard-basecode` template; `plan.md` records the
design decisions and open TODOs (live DB migrate/seed and deploy were still pending at
last commit). Product-facing docs (`README.md`, `plan.md`) are written in Indonesian;
code and identifiers are English.

Stack: Next.js 16 App Router · React 19 · Auth.js v5 (`next-auth@5.0.0-beta`) ·
Drizzle ORM + Postgres (`postgres-js`) · Tailwind v4 · shadcn on `@base-ui/react`
primitives (not Radix) · Zod v4 · pnpm.

```bash

pnpm db:generate         # drizzle-kit generate — after editing src/db/schema/**
pnpm db:migrate          # apply migrations in drizzle/
pnpm db:seed             # idempotent; prints admin login (admin / ChangeMe123! by default)
```

Setup: `cp .env.example .env.local`, set `AUTH_SECRET` (`openssl rand -base64 33`),
start the db container, then `pnpm db:migrate && pnpm db:seed`.

Husky pre-commit runs `lint-staged` (prettier + `eslint --fix` on staged files).

Ports are deliberately offset from the basecode template (app 3000/3001, Postgres
5433, DB name `siber`) so both projects can run at once.

## Architecture

### RBAC is permission-based, never role-based

`src/features/rbac/permissions.ts` — the `PERMISSIONS` const (`"<resource>:<action>"`,
e.g. `notes:create`) — is the single source of truth. The `db:seed` script writes these
keys into the `permissions` table and prunes any that were removed. **Adding a
permission:** add the const, add it to a role's set in `src/db/seed.ts`, re-run the
seed. Roles (`admin`, `member` seeded; more are just rows) are named permission
bundles; application code checks permissions, never role names.

Checks: `can(session, perm)` / `canAny` / `canAll` (`rbac/can.ts`) for UI gating;
`requirePermission(perm)` / `assertPermission(session, perm)` (`rbac/guard.ts`, throw
`ForbiddenError` / `UnauthenticatedError`) at the top of every Server Action and route
handler.

### Auth enforcement is layered — the proxy is not the boundary

1. `src/proxy.ts` (`auth()` wrapper) redirects unauthenticated visitors away from
   `/dashboard/*` only. Next.js doesn't treat Server Actions as routes, so this can
   silently stop covering one.
2. `src/app/dashboard/layout.tsx` re-checks `auth()`.
3. **Each Server Action / route handler calls `requirePermission()` itself** — this is
   what actually protects data. Don't rely on a hidden button or the proxy.

Permissions are resolved once at sign-in (`jwt` callback in `features/auth/config.ts`,
via `getUserRolesAndPermissions()`) and baked into the JWT. Role/permission changes
take effect on the user's **next sign-in**. Sessions are JWT-strategy; the Drizzle
adapter persists users/accounts and is ready for OAuth later. Login is a Credentials
provider keyed on username **or** email + bcrypt hash.

### Notes and Announcements are one feature

Identical shape → one `posts` table split by a `type` enum (`"note"` | `"announcement"`),
one implementation in `src/features/posts/`, one route tree
`src/app/dashboard/[section]/*`. `features/posts/section.ts` maps the URL segment
(`notes`/`announcements`) ↔ `PostType`; `features/posts/permissions.ts`
(`POST_PERMISSIONS`) maps `PostType` → the `notes:*` / `announcements:*` permission
namespace. Add behavior once, in `features/posts/`.

### Public teaser vs. login-gated content

Public pages `/notes` and `/announcements` call `listPostsPublic()`, which **never
selects the `content` column** — title + excerpt + date only. Full markdown content
renders only at `/dashboard/[section]/[id]`, behind the proxy gate.
`react-markdown` + `remark-gfm` + `@tailwindcss/typography` (`prose`), and only on that
full-content page.

### Kas ledger

`kas_transactions`: `amount` is an integer (Rupiah, always positive), `type` is an
`in`/`out` enum. Running balance is computed on the fly (`getKasBalance()` = Σin − Σout),
not stored. `userId` = who the transaction is _about_ (nullable; general expenses have
none); `createdBy` = the admin who recorded it. Per-person dues total
(`getUserKasContribution()`) counts `in` only and shows on the profile page.

### File uploads

`src/features/files/` + the `attachments` table (metadata only). Bytes live on disk
under `env.UPLOAD_DIR` (`./uploads` locally; the `uploads` Docker volume mounted at
`/app/uploads` in prod — `docker/Dockerfile` pre-creates it `chown`ed to the runtime
user so the volume is writable). Keys are generated server-side and fanned into two
subdir levels; `resolveStoragePath()` refuses any key that escapes the root.

Two Node-runtime Route Handlers (not Server Actions — PPT/PDF exceed the 1 MB action
body cap): `POST /api/uploads` (guard `files:upload`, enforces `MAX_UPLOAD_MB`) and
`GET /api/files/[id]` (guard `files:read`, streams from disk; `inline` disposition for
images/PDF, `attachment` otherwise). Both use `guardErrorResponse()` from
`rbac/guard.ts` to turn a thrown guard error into 401/403.

The notes/announcement editor (`MarkdownEditor`, wired into `PostForm` via RHF
`Controller`) takes drag-drop / paste / picker uploads and inserts
`![name](/api/files/<id>)` (images) or `[📎 name](…)` (everything else) at the cursor.
`/dashboard/files` is the standalone library (list / delete / copy-link). Because
files are login-gated, embedded images only render for signed-in viewers — not on the
public `/notes` list.

Attachments are **not** linked to posts by a foreign key — a post only references a
file by its `/api/files/<id>` URL inside `content`. So an abandoned draft, a removed
`![](…)`, or a deleted post all leave the file orphaned (no error, just junk on the
volume). `pnpm files:gc` (`src/db/gc-files.ts`) sweeps attachments older than 24h whose
id appears in no post content or kas description — dry-run by default, `--delete` to
act.

### Env validation

`src/config/env.ts` parses `process.env` with Zod at module load and throws on missing
vars. It sits in the route import chain, so `next build` needs real-looking placeholder
values — see the `ENV` lines in `docker/Dockerfile`. Standalone scripts that run
outside `next` (`drizzle.config.ts`, `src/db/seed.ts`, `playwright.config.ts`) call
`loadEnvConfig(process.cwd())` themselves before importing anything that reads env.

### Conventions

- **Feature folders**: `src/features/<name>/` with `actions.ts` (`"use server"` mutations,
  each returning `{ error?: string }` on validation failure and `redirect()`ing / calling
  `revalidatePath()` on success), `queries.ts` (reads), `schema.ts` (Zod), `components/`.
- **Drizzle schema**: tables in `src/db/schema/*.ts`, re-exported from `index.ts`;
  relations isolated in `relations.ts`. Migrations in `drizzle/` — generate, don't
  hand-write.
- **Path alias**: `@/*` → `src/*`.
- **Sidebar** (`features/dashboard/nav-items.ts`): icons are string keys, not component
  refs, because the array crosses a Server→Client boundary; the client resolves keys to
  icons. Items are permission-filtered for UX only.
- **shadcn `Button`**: render as a link with `nativeButton={false}` + `render={<Link …/>}`.
- Formatting helpers (`id-ID` locale) in `src/lib/format.ts`: `formatDate`, `formatRupiah`.
